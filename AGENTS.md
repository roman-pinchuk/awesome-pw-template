# Repository instructions

## Verification

- Use the devcontainer for normal work; it matches the Playwright image used in CI and includes browsers.
- Install and upgrade dependencies inside the devcontainer so `package-lock.json` is generated with the CI-compatible toolchain.
- Browsers are already included in the devcontainer; do not run `npx playwright install` there.
- After TypeScript or test changes, run `npm run check` (`verify:playwright`, script tests, lint, then typecheck).
- Run the focused suite with `npm run test:ui`, `npm run test:api`, or a specific file with `npx playwright test tests/<path>.spec.ts`.
- UI projects are `chromium`, `firefox`, and `webkit`; UI tests depend on the `setup` project, which creates `.playwright/auth/user.json`.
- API tests require a valid `API_BASE_URL` and `API_KEY`; local configuration is loaded from ignored `.env.local`.
- For UI-only local runs, `API_BASE_URL` is still required because the Playwright config validates all environment settings at startup.
- CI uses `.env.production` through dotenvx and `DOTENV_PRIVATE_KEY_PRODUCTION`; do not commit credentials or edit ignored environment files into source control.

## Architecture

- Keep domain models, factories, journeys, and assertions in `business/`; keep transport, fixtures, configuration, and utilities in `infrastructure/`.
- `pages/` contains thin page objects and reusable components; multi-page behavior belongs in `business/*.journey.ts`, not in page objects or duplicated tests.
- API transport returns raw Playwright `APIResponse` values; domain validation belongs in `business/api/assertions/`.
- API fixture `apiObjects` owns generated collection scopes and cleanup; tests should not add repetitive `try/finally` cleanup.
- Use the validated configuration from `infrastructure/config/env.ts`; do not read environment variables directly in tests.
- Route constants are centralized in `business/constants.ts`; page objects should navigate through their injected Playwright `Page` rather than duplicating route strings.

## Conventions

- Add UI tests under `tests/ui/` and API tests under `tests/api/`; preserve the existing `@CASE-*` tags when changing catalogued cases.
- Keep `package-lock.json` synchronized with `package.json`; rebuild it inside the devcontainer when dependencies change.
- The README dependency/security matrix is generated by the Snyk workflow; do not hand-edit the marked matrix section.
- Reports and runtime artifacts (`test-results/`, `playwright-report/`, `blob-report/`, `allure-results/`, and `ctrf/`) are generated outputs and should not be committed.
